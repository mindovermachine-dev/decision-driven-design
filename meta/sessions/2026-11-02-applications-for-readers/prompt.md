# Prompt — applications/ for readers, 2026-11-02

The session had no bundled prompt. Its charter is Emil's message below, verbatim, and Claude's
reading of it. Per `DDD-dec-20`, this file is committed before any other work, so the session's
scope is fixed at arrival.

## Emil

> the what.md in the SDLC reads as canon, what decisions where are everything now etc. It should
> read as an application that humans can read and use. the same for everything else in
> applications

## Claude's reading of the charter — UNVERIFIED, Emil review

The documents under `applications/` are written as decision records. They open with where they
came from and which rulings govern them, and their running text carries decision ids, Product
Framework section numbers and register markers. A reader who wants to *use* the application must
read through the record of how it was decided.

The charter asks for the opposite order. Each document should read as something a practitioner
can pick up and use, with the record of how it was decided kept available but out of the way.

This session does not change what any document says. It changes how it is presented, and where
the decision trail lives. A rewrite that changes a rule is out of scope. Any rule the rewrite
cannot state without changing it is reported, not fixed.

## Gates

**Gate 1 — the format, proposed and demonstrated.** A survey of every document under
`applications/`; a proposed format for the folder; one document's opening rewritten as a
demonstration; predictions for Gate 2. Stop for Emil's ruling.

**Gate 2 — the rewrite.** Each document rewritten to the ruled format, one commit per document,
each with an equivalence table showing that no rule was lost or changed. Stop for Emil's review.

**Gate 3 — first contact.** The rewritten `what.md` read by a reader who has not seen the old one,
on a task the old one should have supported. Stop for Emil's ruling on the result.
